# PW Scale MAC Mobility + HA

This recipe builds a 200-service EVPN-SI VPLS scale test between PE-4 and
RR-SA-2, drives 400 unknown-unicast L2 StreamBlocks through DNAAS, verifies
bidirectional MAC learning per service, then runs parameterized HA scenarios on
the scaled state.

## Topology

PE-4 and RR-SA-2 use matched service indexes and route-targets:

| Field | Rule |
|---|---|
| Global service index | `service_offset + local_index`, where `local_index` is `1..scale` |
| Service | `EVPN_PW_S<global_index:03d>` |
| Inner VLAN | `3100 + global_index` for default run (`3101..3300`) |
| EVI | `<inner_vlan>` |
| Route-target | `1234567:<inner_vlan>` under SI `l2vpn-vpls` only; native `l2vpn-evpn` RTs must stay absent so MACs are PW-taught instead of RT-2-taught |
| PE-4 RD | `4.4.4.4:<inner_vlan>` |
| RR-SA-2 RD | `2.2.2.2:<inner_vlan>` |
| PE-4 EVPN BGP AS | `1234567` |
| RR-SA-2 EVPN BGP AS | `123` |
| PE-4 site-id | `10000 + global_index` |
| RR-SA-2 site-id | `20000 + global_index` |
| Label block | `label-block-size 8`; budget ordinal `global_index - 1` (`8` slots per service) |
| PE-4 AC | `ge100-18/0/0.<inner_vlan>` |
| PE-4 wire encapsulation | outer `219`, inner `<inner_vlan>` |
| RR-SA-2 AC | `bundle-100.<inner_vlan>` |
| RR-SA-2 wire encapsulation | outer `4`, inner `<inner_vlan>` |
| Spirent to RR-SA-2 | outer `215`, inner `<inner_vlan>`; B-15 rewrites outer `215` to wire outer `4` |

DNAAS bridge-domain and sub-interface suffixes are not required to match the
user-facing VLAN. For example, PE-4 traffic sent as outer `219` can legitimately
traverse a `.213` DNAAS fabric hop when the BD membership and VLAN manipulation
translate it. The runtime gate validates the live DNAAS diagnosis and expected
DUT AC readiness rather than treating suffix mismatches as failures.

The service matrix is generated by `shared/pw_scale_builder.py`. Do not hand-edit
individual service rows in the recipe.

The generator fails before any config is rendered if any collision-sensitive
value overlaps: service name, inner VLAN, EVI, RT, RD, AC name, site-id,
label-block ordinal, stream name, ownership tag, source MAC, or unknown-unicast
destination MAC. It also refuses inner VLAN windows outside the valid
`1..4094` VLAN tag range.

Each StreamBlock uses a deterministic unique source MAC for learning and a
deterministic unlearned unicast destination MAC (`02:aa:*`). Broadcast
destinations are intentionally not used; this is unknown-unicast traffic.

## Runtime Parameters

| Parameter | Default | Purpose |
|---|---:|---|
| `scale` | `200` | Number of matched PW services. Use `10` for smoke. |
| `service_offset` | `0` | Moves the global-index and inner-VLAN window. Offset `200` uses `3301..3500`. |
| `chunk_commit_size` | `25` | Services per paired PE-4/RR-SA-2 `dnos_multi_device_commit`. |
| `stream_strategy` | `one_per_pw_400` | One StreamBlock per direction per service for per-PW stats. |
| `ha_mode` | `core3` | `skip`, `switchover_only`, `core3`, or `full_7_chunked`. |
| `wave_size` | `50` | StreamBlocks activated per wave. |
| `wave_spacing_sec` | `5` | Delay between activation waves. |
| `rate_mbps` | `1` | Rate per StreamBlock. |
| `dnaas_preflight_mode` | `smart` | Covers all `2 * scale` PE-4/RR-SA-2 frame recipes with aggregate inner-VLAN range checks plus representative live DNAAS preflights. Use `full` only for exhaustive per-service debug. |
| `dnaas_parallelism` | `20` | Parallel DNAAS preflight calls. Smart mode needs only a small number of calls; full mode still scales with `2 * scale`. |
| `allow_existing_service_window` | `false` | Use only for post-config/post-restart prerequisite validation, where the generated services are expected to already exist before traffic or HA starts. |

## Operation

Dry-run generation:

```bash
python3 orchestrator.py --dry-run --scale 10 --ha-mode skip
```

Full default run:

```bash
python3 orchestrator.py --scale 200 --ha-mode core3
```

Run only a phase:

```bash
python3 orchestrator.py --phase verify_pw_establishment --scale 200
```

Run the controlled mass MAC mobility phase after the two baseline modifier
streams are learned:

```bash
python3 orchestrator.py --phase mass_mobility --scale 200 --traffic-strategy modifier --ha-mode skip
```

This creates two reverse modifier StreamBlocks, deactivates other known
StreamBlocks, activates only the reverse pair, and verifies the 200 PE-4 source
MACs moved local on RR-SA-2 while the 200 RR-SA-2 source MACs moved local on
PE-4. The reverse streams use fresh unknown-unicast destination MAC ranges
`02:aa:fa:01:00:01..02:aa:fa:01:00:c8` and
`02:aa:fb:01:00:01..02:aa:fb:01:00:c8`, so the mobility proof is based on the
source MAC move, not on prior destination learning.

If HA is run after this phase, keep the moved-state verifier active:

```bash
python3 orchestrator.py --phase ha --scale 200 --ha-mode core3 --expected-mac-state moved
```

Run repeated mobility before HA:

```bash
python3 orchestrator.py --phase multi_mobility --scale 200 --move-cycles 2
```

Each cycle activates the baseline streams and verifies original ownership, then
activates the reverse streams and verifies moved ownership. The final state is
`moved`, so follow-up HA should use:

```bash
python3 orchestrator.py --phase ha --scale 200 --ha-mode safe_no_bgp --expected-mac-state moved
```

Cleanup, if the run created services:

```bash
python3 orchestrator.py --phase cleanup --scale 200
```

## Safety Gates

The recipe refuses to proceed past prerequisites unless these checks pass:

- PE-4 and RR-SA-2 identity locks via `show system version`.
- The generated service window is internally unique and does not already appear
  in live flattened config on PE-4 or RR-SA-2.
- The label-pool gate rejects SW-253359 signatures (`bgp-vpls: 0 labels, N/A`)
  before config is pushed.
- The active bgp-vpls label pool must be large enough for the requested scale:
  `scale * label-block-size * 2` labels per DUT, plus existing non-target SI
  services. DNOS exports two VPLS label-block routes per service (local-site
  and remote-site offsets), so with `label-block-size 8`, a 200-service run
  requires at least `3200` bgp-vpls labels per DUT before headroom. A pool of
  `2048` can still produce `Failed to allocate label ... abort export`, missing
  BGP L2VPN-VPLS prefixes, and empty VPLS PW tables.
- The configured bgp-vpls label pool must also be active. If
  `show mpls label-allocation tables` reports `Configured` as large enough but
  `In use` is still smaller, or prints `Configured values differ from current
  in use values, restart system to apply new values`, `/TEST` blocks the run
  with the SW-253359 remediation instead of creating streams or starting HA.
- DNAAS preflight runs before config with `READY` or `NEEDS_AC` accepted, then
  runs again after config and requires `READY` before any Spirent stream is
  created.
- Spirent session and soft stream-capacity budget are valid.
- DNAAS preflight is READY or NEEDS_AC for each requested inner VLAN.
- PE-4 does not match SW-253359 (`bgp-vpls: 0 labels, N/A`).
- HA readiness is acceptable when `ha_mode` is not `skip`.

Config is applied in paired PE-4/RR-SA-2 chunks with `dnos_multi_device_commit`.
The default chunk size is 25 services, so a full 200-service run uses 8 paired
commits.

## Recovery

If a config chunk fails, the orchestrator stops at the first failing chunk and
writes the failure details under the run directory. Already committed chunks are
tracked in `~/SCALER/TEST/active_test_session.json`. Run cleanup with the same
`scale` and `service_offset` to remove the service window in reverse chunk order.

If the SW-253359 label-pool gate fails, do not continue with workaround config.
The symptom means the cluster label pool is not active for bgp-vpls after
restart/preservation. Keep `routing-options bgp-vpls-label-block-size` at or
above the required budget, perform the documented full cold `request system
restart` on the affected cluster, then re-run `show mpls label-allocation
tables`; bgpd/container/NCC restarts and switchover are not accepted recovery
for this gate. If `In use` still does not match `Configured` after a full cold
restart, capture the evidence and debug the device state first.

If MAC learning fails after DNAAS and Spirent proof pass, stop the scenario and
invoke `/debug-dnos` with the service name, inner VLAN, source MAC, origin DUT,
partner DUT, and event timestamp. Remote MAC learning must be source-qualified
as `v>` / VPLS PW; `B>` / RT-2 evidence is a failure for this PW-teaching
recipe. Do not clear MAC tables before evidence is captured.
